# i18n — Internationalization

## Rule: No Hardcoded Strings (MANDATORY)

ALL user-facing text MUST use i18n translation keys — never hardcode strings in components.

```tsx
// ❌ Wrong
<p>Enter your phone number</p>
<button>Submit</button>

// ✅ Correct
import { useTranslation } from "react-i18next";
const { t } = useTranslation();
<p>{t("pagoMovil.phoneLabel")}</p>
<button>{t("common.submit")}</button>
```

## Before Adding a Translation Key

1. **Search** if the key already exists:
   ```bash
   grep -r "pagoMovil.phoneLabel" src/Infra/lang/
   ```
2. If found → use it
3. If NOT found → create it in **ALL** language files

## Adding New Translation Keys

Update every language file simultaneously:
```bash
# Find all translation files
find src/Infra/lang -name "*.json" -o -name "*.ts"
```

Example — adding to each:
```json
// en.json
{
  "pagoMovil": {
    "phoneLabel": "Phone number",
    "selectAccount": "Select account"
  }
}

// es.json
{
  "pagoMovil": {
    "phoneLabel": "Número de teléfono",
    "selectAccount": "Seleccionar cuenta"
  }
}
```

## Key Naming Convention

```
[feature].[component].[description]
```

Examples:
- `pagoMovil.form.phoneLabel`
- `common.actions.submit`
- `withdrawal.steps.selectAccount`
- `errors.network.timeout`

## Post-Task i18n Checklist

- [ ] No hardcoded strings in any component touched
- [ ] Verified no duplicate keys exist
- [ ] New keys added to ALL language files
- [ ] Used `t()` from `useTranslation()` hook, not direct import
