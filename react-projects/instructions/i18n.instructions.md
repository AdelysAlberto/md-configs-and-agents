# i18n / UI Literals — fansity-client

## Regla fundamental

**Todo texto visible al usuario DEBE estar definido en `src/locales/en/`.  
❌ Nunca hardcodear strings de UI directamente en JSX.**

## Stack

- **i18next** + **react-i18next** (ya instalados)
- Un único idioma: **English (en)**
- Config: `src/providers/i18N/i18n.config.ts`

## Estructura de archivos

```
src/locales/
  en/
    common.ts     # Literales globales: appName, loading, error, cancel...
    auth.ts       # Login, register, recover password
    [feature].ts  # Un archivo por namespace / feature
src/providers/i18N/
  i18n.config.ts  # Inicialización de i18next
  index.ts        # Barrel export
```

## Namespaces

| Namespace | Archivo | Uso |
|---|---|---|
| `common` | `src/locales/en/common.ts` | Textos globales compartidos |
| `auth` | `src/locales/en/auth.ts` | Login, registro, recovery |
| `[feature]` | `src/locales/en/[feature].ts` | Textos propios de cada feature |

## Uso en componentes

```typescript
// Un namespace
const { t } = useTranslation("auth");
t("login.title")           // → "Welcome back"

// Múltiples namespaces
const { t } = useTranslation(["auth", "common"]);
t("auth:login.title")      // namespace explícito
t("common:appName")        // "Fansity"
```

## Flujo para agregar texto nuevo

1. **¿El literal ya existe?**
   - Buscar en `src/locales/en/` antes de crear uno nuevo
   - Si existe en `common.ts`, reutilizarlo
2. **¿No existe?**
   - Agregarlo al archivo de namespace correspondiente (`auth.ts`, etc.)
   - Si no hay namespace para la feature, crear `src/locales/en/[feature].ts`
3. **Usar `t()` en el componente** — nunca el string directo

## Estructura de un archivo de locale

```typescript
// src/locales/en/myFeature.ts
export const myFeatureEn = {
  sectionName: {
    title: "...",
    subtitle: "...",
    // campos del formulario
    fieldLabel: "...",
    fieldPlaceholder: "...",
    // acciones
    submitButton: "...",
    cancelButton: "...",
    // mensajes de estado
    successMessage: "...",
    errorMessage: "...",
    // validación (si se usan en Zod como mensajes)
    validation: {
      required: "This field is required",
      invalid: "...",
    },
  },
} as const;
```

## Reglas adicionales

- ✅ **Solo inglés** — No mezclar idiomas, no texto en español en la UI
- ✅ `as const` en todos los archivos de locale para tipado literal
- ✅ Registrar el namespace en `i18n.config.ts` bajo `resources.en`
- ❌ No usar `defaultNS` implícitamente en componentes — ser explícito con el namespace
- ❌ No concatenar strings con `+` para formar mensajes — usar interpolación `{{variable}}`

## Agregar nuevo namespace

```typescript
// 1. Crear src/locales/en/myFeature.ts con export myFeatureEn = {...} as const
// 2. Registrar en src/providers/i18N/i18n.config.ts:
resources: {
  en: {
    auth: authEn,
    common: commonEn,
    myFeature: myFeatureEn,  // ← agregar aquí
  },
},
```
