
# Internationalization (i18n)

## react-i18next Guidelines

All user-facing text must use `t('key')` keys. Never hardcode strings in components.

### Translation File Structure

```
public/locales/
├── en/
│   └── translation.json
└── es/
    └── translation.json
```

### Usage Pattern

```typescript
import { useTranslation } from 'react-i18next';

const UserProfile = () => {
  const { t } = useTranslation();

  return (
    <div>
      <h1>{t('profile.title')}</h1>
      <p>{t('profile.welcome', { name: userName })}</p>
    </div>
  );
};
```

### Namespace Organization

- Group keys by feature/domain: `profile`, `auth`, `common`, `dashboard`, etc.
- Use nested keys for complex phrases: `auth.login.button = "Iniciar sesión"`
- Never use root-level keys without a namespace prefix.

### Pluralization

Use `i18next` pluralization function for counts:

```typescript
{t('items.count', { count }, [count])}
```

### Right-to-Left (RTL) Support

- All CSS must be RTL-aware using `direction` and `text-align` properties.
- Test components with `dir="rtl"` attribute.
- Mirror logical properties (`margin-inline-start`, `text-align`) where appropriate.

### Translation Quality

- All translation keys must have values in both `en` and `es` namespaces.
- Never leave translation keys without a value (empty strings permitted only with comment explanation).
- Use `i18next-nexttranslate` for visual translation debugging.
