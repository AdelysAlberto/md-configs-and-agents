# Internationalization (i18n) Standards

## 1. Rule: All User-Facing Text Must Be Translated

Never hardcode raw text that appears in the UI. Every string visible to users must go through the i18n system.

```typescript
// ❌ WRONG — hardcoded text
<Button>Back</Button>
<Text>Save changes</Text>

// ✅ CORRECT — translated key
const { t } = useTranslation();
<Button>{t('back')}</Button>
<Text>{t('saveChanges')}</Text>
```

---

## 2. Supported Languages & Synchronization

All translation keys MUST be maintained across **ALL 5 supported languages** synchronously:
- `es.json` (Spanish - Default)
- `en.json` (English)
- `fr.json` (French)
- `it.json` (Italian)
- `pt.json` (Portuguese)

Never add, modify, or delete a key in one file without reflecting it in all 5 files.

---

## 3. Strict Anti-Pattern Prohibitions

### ❌ Anti-Pattern 1: Dot-literal Keys in JSON Root
**STRICTLY FORBIDDEN** to create flat keys with dots in JSON files (e.g. `"common.back": "Back"`).
```json
// ❌ WRONG — dot literal in root
{
  "common.back": "Back",
  "common.error": "Error"
}

// ✅ CORRECT — flat universal key
{
  "back": "Back",
  "error": "Error"
}
```

### ❌ Anti-Pattern 2: Duplicating Universal Common Actions
**STRICTLY FORBIDDEN** to duplicate generic actions/verbs per feature or prefix them with screen/domain names (e.g. `incidentCancelButton`, `contactActionCancel`, `deleteAccountCancel`, `navigation.finish`, `commonClose`, `commonSave`).

---

## 4. Universal Common Keys Standard

Always reuse the canonical root keys for universal actions, alerts, and feedback:

| Action / Concept | Key | ES | EN | FR | IT | PT |
|---|---|---|---|---|---|---|
| Cancelar | `cancel` | Cancelar | Cancel | Annuler | Annulla | Cancelar |
| Atrás / Volver | `back` | Atrás | Back | Retour | Indietro | Voltar |
| Cerrar | `close` | Cerrar | Close | Fermer | Chiudi | Fechar |
| Finalizar / Terminar | `finish` | Finalizar | Finish | Terminer | Termina | Finalizar |
| Guardar | `save` | Guardar | Save | Enregistrer | Salva | Salvar |
| Guardar cambios | `saveChanges` | Guardar cambios | Save changes | Enregistrer les modifications | Salva modifiche | Salvar alterações |
| Eliminar / Borrar | `delete` | Eliminar | Delete | Supprimer | Elimina | Excluir |
| Reintentar | `retry` | Reintentar | Retry | Réessayer | Riprova | Tentar novamente |
| Refrescar / Actualizar | `refresh` | Refrescar | Refresh | Actualiser | Aggiorna | Atualizar |
| Error genérico | `error` | Error | Error | Erreur | Errore | Erro |
| Éxito genérico | `success` | Éxito | Success | Succès | Successo | Sucesso |
| Error de conexión | `networkError` | Error de conexión | Connection error | Erreur de connexion | Errore di connessione | Erro de conexão |
| OK / Confirmar | `ok` | OK | OK | OK | OK | OK |
| Aceptar | `accept` | Aceptar | Accept | Accepter | Accetta | Aceitar |
| Rechazar | `decline` | Rechazar | Decline | Refuser | Rifiuta | Recusar |
| Continuar | `continue` | Continuar | Continue | Continuer | Continua | Continuar |

---

## 5. Domain-Specific Keys Naming

For text specific to a domain or screen, use descriptive camelCase or structured nesting for complex submodules (e.g. `maneuver`, `navigation`, `routes`):
- `registerEmailLabel`
- `deleteAccountTitle`
- `deleteAccountConfirmMessage`
- `routes.calculating`

Never duplicate a universal action when a screen button simply says "Cancel", "Back", "Close", or "Finish".

---

## 6. Dynamic Values in Translations

Use interpolation parameters — never string concatenation:
```typescript
// ❌ WRONG
const message = t('searchRecentFrom') + ' ' + locationName;

// ✅ CORRECT
const message = t('searchRecentFrom', { name: locationName });
// JSON: { "searchRecentFrom": "From {{name}}" }
```
